# Manuscript-writing instructions (Dr. Uday Pratap Singh)

These rules apply to every journal manuscript, book chapter or report written in this repository.
If a target journal's author guide conflicts with a rule here, follow the journal and say so.

## 1. Research integrity (non-negotiable)
- Report only what the data, code and analyses actually show. No overclaiming: every claim states
  its scope (data set, conditions, sample size) and its limits.
- Never invent results, numbers, data sets, citations, DOIs, quotes or author names. If something is
  unknown or unverified, say so or leave a clearly marked placeholder (e.g. `[VERIFY]`).
- Negative, null and non-significant results are reported alongside positive ones, not hidden.
- Every number in the text, tables and figures must be traceable to a script/result file in the repo.
- Assumptions and modelling choices are stated explicitly where they are used and in the limitations.

## 2. References and citations
- Cite only **published, peer-reviewed** work: journal articles and peer-reviewed conference
  proceedings (e.g. ACM SIGCOMM, USENIX NSDI, IEEE INFOCOM), books, standards, and official data
  sets/documentation. **Not allowed:** arXiv/SSRN/Research Square/Preprints.org preprints,
  unpublished manuscripts, theses unless unavoidable, blogs, news articles.
- Every reference must be real and checked against its DOI (or ISBN / official URL for standards and
  data sets) before inclusion. DOIs are given in full: `https://doi.org/10.xxxx/xxxxx`.
- Every reference in the list is cited in the text at the exact sentence it supports, and every
  citation in the text appears in the list.
- Prefer recent work (roughly the last 5 years) for the state of the art; cite older work only for
  foundational methods, data sets or definitions.
- Use the citation style required by the target journal (default: IEEE numbered style `[1]`, `[2, 3]`).

## 3. Writing style
- Human, natural academic prose: varied sentence length, concrete statements, the author's voice
  ("we"), specific numbers instead of adjectives.
- Avoid AI-style patterns: stock openers ("In today's rapidly evolving..."), inflated adjectives
  ("groundbreaking", "seamless", "pivotal", "delve", "leverage", "robust" used loosely), formulaic
  triplets, excessive bullet lists in the main text, repeated summary sentences, and rhetorical questions.
- One idea per paragraph; each paragraph starts with its point. No repetition across sections.
- Hedge exactly as much as the evidence requires: no more, no less.

## 4. Manuscript structure (standard scientific article)
Title; author list and affiliations; Abstract (structured if the journal asks; states problem,
method, data, main quantitative results and scope); Keywords; Highlights (if required);
1 Introduction (problem, gap, **explicit novelty and contributions**); 2 Related Work (recent,
organised by theme, ending with how this work differs); 3 Problem formulation / Preliminaries;
4 Method; 5 Experimental setup (data, baselines, metrics, statistics, reproducibility);
6 Results; 7 Discussion (interpretation, implications, limitations, threats to validity);
8 Conclusion and future work; Declarations (funding, competing interests, data and code
availability, CRediT author contributions, AI-assistance disclosure if the journal requires it);
References; Appendices only if essential.

## 5. Novelty
- State the novelty in the Introduction as a short, specific list of contributions, each one
  checkable against prior work.
- Position every contribution against the closest recent published work (named and cited) and say
  precisely what is new and what is reused.
- Do not claim "first" unless a documented literature search supports it; prefer "to our
  knowledge" with the search scope stated.

## 6. Equations
- All displayed equations in LaTeX, numbered consecutively `(1), (2), ...`, referred to in the text
  as "Eq. (3)". Every symbol is defined at first use, with units. Notation is consistent throughout.

## 7. Figures
- Clean "presentation (PowerPoint) style": simple layouts, no 3-D effects, no gradients, no chart junk.
- **Black and white only**; series distinguished by line style, marker shape or hatching, never by colour.
- **Sans-serif font (Arial/Helvetica), 12 pt at the final printed size** for all labels, ticks,
  legends and annotations; axis labels include units.
- Export as vector (PDF/EPS) or ≥600 dpi TIFF; sized to the journal's column width.
- Every figure is generated by a script in the repository; the script name is recorded.
- Every figure is cited in the text before it appears and is **discussed**: what it shows, the key
  observation, and what it means. A caption alone is not enough.

## 8. Tables
- Every table is cited in the text and discussed (the main comparison and its meaning).
- Units in column headers; same number of significant digits per column; best value marked only if
  the difference is statistically supported; statistical notation (e.g. `*`, `†`) defined in the caption.

## 9. Statistics and reporting
- Name the test, the unit of analysis, n, the correction for multiple comparisons, effect sizes and
  confidence intervals, not p-values alone. Separate pre-registered (confirmatory) analyses from
  exploratory ones.

## 10. Supplementary material
- Anything not essential to the main argument goes into a separate Supplementary file: extra tables,
  sensitivity analyses, full per-case results, extended proofs, implementation details,
  pre-registration records and development history. The main text references it as "Supplementary
  Table S1", "Supplementary Fig. S2", etc.

## 11. Before delivering a manuscript, check
- [ ] every number traces to a result file; [ ] every citation verified (DOI resolves, metadata
  correct) and peer-reviewed; [ ] every figure/table cited and discussed; [ ] equations numbered and
  symbols defined; [ ] figures black-and-white, 12 pt sans-serif; [ ] novelty stated and positioned
  against recent work; [ ] limitations and negative results reported; [ ] no AI-style phrasing;
  [ ] supplementary file prepared and cross-referenced.
